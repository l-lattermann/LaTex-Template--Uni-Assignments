# Compliance checklist — DLBCSAPM01 project report

Sources: `Guidelines Project Report.pdf`, `task_project_report_dlbcsapm01_2.pdf`,
`sidenotes from liveseesion.txt`, `sidenotes from teams channel.txt`,
`outline_projektbericht.txt`. Newer tutor rulings override older ones.

## Formal

- [ ] 7–10 pages of text. Title page, TOC, lists and bibliography excluded;
      essential appendix content would count, so no appendix is used.
- [ ] Proportions: introduction 10–15 %, main body 70–80 %, conclusion 10–15 %.
- [ ] Third person throughout, no first-person perspective.
- [ ] One consistent tense; present preferred, no jumps.
- [ ] Factual, precise register. No colloquialisms, no embellishment, no
      convoluted sentences. Continuous prose, not bullet lists.
- [ ] Maximum three heading levels.
- [ ] List of tables included (mandatory, because tables are used).
      No list of figures — the report contains no figures by design.
- [ ] List of abbreviations trimmed to the abbreviations actually used.
- [ ] Anti-plagiarism pledge submitted electronically before upload,
      otherwise Turnitin blocks the submission.

## Citation

- [ ] APA, in-text citations with **page numbers** — the only explicitly named
      point-loser.
- [ ] Direct quotations marked; a reference list without in-text citations
      counts as plagiarism (zero points).
- [ ] Academic sources preferred; no commercial websites as research basis.
      There is no coursebook — own research is part of the grade.
- [ ] Core reading: Kerzner (**2022, 13th ed.** — the task sheet lists the 2009
      10th ed.; cite what was read and footnote the substitution), Kelly (2019),
      Scrum Guide (2020), PMI Agile Practice Guide (2017), PMBOK 7 (2021).
- [x] **SBOK and Wysocki (2019): decided not to use.** The SBOK was read and
      dropped — vendor certification material, and its refinement guidance
      assigns refinement to the Product Owner alone, which contradicts the
      "refined *with* the Scrum team" argument in 3.3. Wysocki was never
      obtained and is not needed: chapter 4 has Kerzner, PMBOK 7, the Agile
      Practice Guide and Mishra & Alzoubi covering both sides.
- [x] Final source set is **14**, listed in `REFERENCES.md` and `references.bib`.
- [ ] Text written by hand, not by AI (Turnitin AI detection in use).

## Where literature is needed

Rule of thumb: **cite the concept, own the decision.** Named concepts get a
page-numbered source; anything invented for this project stays uncited.

## Content

- [ ] All three task questions answered and **balanced** — imbalance is the
      named mark-loser, not missing detail.
- [ ] Everything applied concretely to the recipe app; never generic. This is
      most critical in chapter 4.
- [ ] Written as if the project had actually been carried out.
- [ ] Assumptions (team, sprint length, time, budget, people) stated explicitly.
- [ ] The report ends at planning: sprint zero, initial backlog, first sprint.
      No multi-sprint history, no second full waterfall plan.
- [ ] User stories in the body, exactly the format
      "As a [type of user], I want [function], so that [benefit]",
      varied personas — never "As a user".
- [ ] The initial backlog consists of exactly the same ten stories.
      No epics, no invented extra items.
- [ ] Refinement **and** sprint planning both covered; refinement first.
- [ ] Scrum events (sprint review, retrospective, daily) described only in
      chapter 4, not twice.
- [ ] Conclusion is a separate chapter, not a repeat of the comparison.

## Deliberately excluded

Figures and any visuals in the body, acceptance/test criteria, epics, story
mapping, persona journeys, agile history, stakeholder and risk analysis,
resource/cost planning, phase planning, WBS, market analysis, technical/app
descriptions, separate theory chapter, appendix.

Planning poker is not excluded outright, but it belongs to task 3 — a passing
mention inside sprint planning at most, never a section of its own.
